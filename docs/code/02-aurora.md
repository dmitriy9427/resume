# 2. Северное сияние

[src/modules/aurora/index.ts](../../src/modules/aurora/index.ts) — WebGL без библиотек, около 3 КБ.

## Где на экране

Фон первого экрана: цветные ленты плавно перетекают, как северное сияние, и чуть тянутся к курсору.
Справа светлее, к левому краю и вниз гаснут — текст поверх читается.

## Что делает

- Рисует фон фрагментным шейдером на всю площадь `<canvas>`.
- Берёт цвета из CSS-переменных `--aurora-1/2/3` — их меняют в стилях, а не в коде.
- Тянет пятно света к курсору с инерцией.
- Рисует кадры, только пока первый экран виден; плотность — не больше 1,5.
- «Уменьшить движение» — один неподвижный кадр; нет WebGL — виден CSS-градиент под canvas.

## Код по частям

### Подготовка WebGL — «полноэкранный треугольник»

```ts
const gl = canvas.getContext('webgl2', { antialias: false, premultipliedAlpha: false })
if (!gl) return undefined
…
gl.bufferData(gl.ARRAY_BUFFER, new Float32Array([-1, -1, 3, -1, -1, 3]), gl.STATIC_DRAW)
```

- Нет WebGL2 — модуль просто выходит, под canvas остаётся CSS-градиент.
- Рисуем **один треугольник**, который больше экрана и накрывает его целиком: вершины (−1,−1),
  (3,−1), (−1,3) в координатах экрана от −1 до 1. Всё остальное делает фрагментный шейдер.

### Фрагментный шейдер: шум fbm

```glsl
float noise(vec2 p) {
  vec2 i = floor(p), f = fract(p);
  vec2 u = f * f * (3.0 - 2.0 * f);
  return mix(mix(hash(i), hash(i + vec2(1, 0)), u.x), mix(hash(i + vec2(0, 1)), hash(i + vec2(1, 1)), u.x), u.y);
}

float fbm(vec2 p) {
  float v = 0.0, a = 0.5;
  for (int i = 0; i < 5; i++) { v += a * noise(p); p *= 2.0; a *= 0.5; }
  return v;
}
```

- **`noise`** — «случайные» числа в узлах сетки, плавно смешанные между узлами. `f*f*(3-2f)` —
  сглаживание, чтобы не было видно клеток.
- **`fbm`** («фрактальное броуновское движение») — пять слоёв шума: каждый следующий вдвое мельче
  и вдвое слабее. Крупные формы плюс мелкие детали — «облачная» текстура.

```glsl
float t = uTime * 0.06;
vec2 q = vec2(fbm(p * 1.4 + t), fbm(p * 1.4 - t + 3.7));
float n = fbm(p * 1.2 + q * 1.6 + vec2(t * 0.6, -t * 0.4));
```

Приём **искажения координат шумом**: сначала шум `q`, потом шум от координат, сдвинутых на `q`.
Ленты не просто дрейфуют, а «текут» и закручиваются.

```glsl
vec2 m = uMouse * vec2(uResolution.x / uResolution.y, 1.0);
float glow = smoothstep(0.75, 0.0, distance(p, m));
vec3 c = mix(uColor1, uColor2, smoothstep(0.25, 0.75, n));
c = mix(c, uColor3, smoothstep(0.55, 0.9, q.y) * 0.8);
c += uColor2 * glow * 0.35;
float vignette = smoothstep(1.25, 0.2, distance(uv, vec2(0.65, 0.6)));
color = vec4(c * (0.18 + 0.55 * n) * vignette, 1.0);
```

- Цвет — смесь трёх цветов по значениям шума.
- **Пятно у курсора** — ярче там, где пиксель близко к мыши.
- **Виньетка** — центр яркости правее и выше (0.65, 0.6), к краям и вниз — темнее: там текст.
- Координаты умножены на соотношение сторон — круги остаются кругами на широком экране.

### Цвета — из CSS

```ts
const applyColors = () => {
  const style = getComputedStyle(canvas)
  gl.uniform3fv(u('uColor1'), parseColor(style.getPropertyValue('--aurora-1') || '#5b3df5'))
  …
}
d.listen(document, 'theme:change', () => { applyColors(); draw() })
```

Дизайнер меняет цвета в SCSS, а не в шейдере. `parseColor` понимает `#rgb`, `#rrggbb` и `rgb()`.
Сменили тему — перечитали.

### Курсор с инерцией и кадры

```ts
const mouse = { x: 0.7, y: 0.6, tx: 0.7, ty: 0.6 }
d.listen(window, 'pointermove', (event) => {
  mouse.tx = (event.clientX - rect.left) / rect.width
  mouse.ty = 1 - (event.clientY - rect.top) / rect.height
})

const tick = (_t: number, deltaMs: number) => {
  const dt = Math.min(deltaMs / 1000, 0.05)
  time += dt
  const k = 1 - Math.exp(-dt * 2.5)
  mouse.x += (mouse.tx - mouse.x) * k
  mouse.y += (mouse.ty - mouse.y) * k
  draw()
}
```

- `1 - y` — у шейдера Y растёт вверх, у браузера — вниз.
- **Инерция**: пятно догоняет курсор на долю пути каждый кадр. `1 - exp(-dt·2.5)` — одинаково на
  60 и 144 Гц.
- `time = 8` в начале — первый кадр уже «красивый», а не из нулевого состояния.
- Кадры — из `gsap.ticker`, включаются `onViewport` только пока canvas на экране.

```ts
const dpr = Math.min(window.devicePixelRatio || 1, 1.5)
```

Фон размытый — ретина не нужна. На экране с плотностью 3 это в 4 раза меньше пикселей.

## Что будет, если…

| Сделать | Что сломается |
| --- | --- |
| цвета зашить в шейдер | смена фирменного цвета — правка GLSL, тёмная тема не поменяет сияние |
| рисовать кадры всегда | ноутбук греется, пока человек читает «Проекты» |
| полная плотность пикселей | на ретине — падение FPS ради невидимой разницы |
| без виньетки | имя и подпись теряются на ярком фоне |

## Проверьте себя

1. Сколько слоёв шума в `fbm` и что будет, если оставить один?
2. Почему вершин три, а не четыре?

<details>
<summary>Ответы</summary>

1. Пять. С одним — крупные мягкие пятна без деталей, «пластилин», а не облака.
2. Один большой треугольник накрывает весь экран — нет шва по диагонали, меньше данных; лишнее за
   экраном отсекается.
</details>
